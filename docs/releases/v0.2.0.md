# v0.2.0 — Public site MVP

Date: 2026-08-15

Second tagged release of Tycoma. It ships the **Public Site** epic: anonymous visitors can now
read published content from the Admin Dashboard through a settings- and menu-driven public shell.

## Highlights

- **Public layout shell** (`src/app/(site)/layout.tsx`) — site title/branding (logo from settings)
  and primary navigation resolved from the navigation menu (nested items; `main` slug, fallback to
  the first menu), with a minimal footer. A scoped light-theme stylesheet keeps the public site
  visually separate from the admin dark theme.
- **Home** (`/`) — lists published posts, newest first, with date and excerpt; empty state when no
  published posts exist.
- **Post detail** (`/posts/[slug]`) — published-only, `generateMetadata` (meta title/description,
  canonical from `baseUrl`, `ogImage`), featured image via `next/image` when set.
- **Page detail** (`/[slug]`, top-level) — published-only, same metadata rules; the top-level
  scheme matches the existing `/sitemap.xml` and the public-nav resolver.
- **Taxonomy** — category/tag index pages (`/categories`, `/tags`) with post counts, and detail
  pages listing the published posts in each.
- **Friendly 404** — `not-found` page for missing or unpublished slugs; drafts never leak.
- **Public read use cases** — new published-only reads in the `content` module
  (`application/use-cases/public.ts`): published post/page by slug, list published posts/pages,
  posts by category/tag, and a public-nav resolver. `ListPostsQuery` gained a `tagId` filter.

## Architecture notes

- The public site is a **composition layer** only: `src/app/(site)/**` has no business rules,
  domain entities or Prisma access — everything flows through `content` / `media` application use
  cases via `src/app/_lib/modules.ts`.
- Hexagonal boundaries kept: the new public reads live in `content` (owning module), wired inside
  `content/application/index.ts`; the framework `modules.ts` needed no change.
- Every dynamic route param (`slug`) is Zod-validated.
- No new npm dependency was added. Body is rendered as stored text (matching the admin preview);
  a markdown renderer remains a deliberate follow-up pending dependency approval.

## URL scheme

| Entity | Route |
| ------ | ----- |
| Post | `/posts/[slug]` |
| Page | `/[slug]` (top-level) |
| Category | `/categories/[slug]` |
| Tag | `/tags/[slug]` |

Reserved static segments (`posts`, `categories`, `tags`, `admin`) take precedence over `[slug]`, so
a page whose slug collides with one of those would be shadowed — admin should avoid such slugs.
