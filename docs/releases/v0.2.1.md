# v0.2.1 — Public-site follow-ups, CI hardening, doc sync

Date: 2026-08-15

Patch release on top of `v0.2.0`. Closes the four deferred follow-ups from the Public Site epic
(extract shell components, posts index, page breadcrumb, favicon from settings), tightens CI,
expands the application test surface, and adds the **doc-sync rule** that keeps the project's
five documentation surfaces aligned after every milestone.

## Highlights

- **Public posts index** at `/posts` — full list of published posts (newest first) with SEO
  metadata and a canonical URL. Closes the deferred follow-up P6.
- **Page hierarchy breadcrumb** on `/(site)/[slug]` — walks `parentId` (cycle-guarded) and shows
  only published ancestors, sourced from a new `content.getPageBreadcrumb` use case. Closes P9.
- **Extracted public-site components** — `SiteHeader`, `SiteFooter`, and `PostCard`/`PostList`
  moved into `src/app/(site)/_components/`, replacing inline JSX in the layout/home/posts
  routes. Closes P3.
- **Favicon from settings** — the public layout's `generateMetadata` now exposes
  `settings.faviconMediaId` via the `icons.icon` field when a media asset resolves. Closes P14.
- **CI hardening** — `.github/workflows/ci.yml` now publishes the Next.js build before running
  the unit tests, so the same `next build` invocation the gate runs is exercised end-to-end.
- **Application tests** — login, password-reset, and content-guard paths now have unit tests
  that mock the domain ports only (Node built-in runner, no Docker required).
- **Doc sync rule** — `AGENTS.md` § *Critical rules* (rule 9) and `docs/coding-standards.md`
  § *Doc sync* codify the five-file checklist (README Current State, CHANGELOG, tasks/*,
  AGENTS.md Known technical debt, docs/lessons.md when a durable rule is learned).
- **Testing playbook** — `docs/testing-playbook.md` documents the testing pyramid
  (no mocks in domain, port-only mocks in application), the regression checklist, and the
  smoke-test guidance.

## Architecture notes

- No new module, no new public surface for other modules to depend on. The new public reads
  live in `content/application/use-cases/public.ts` (next to the `v0.2.0` reads); the
  framework composition root (`src/app/_lib/modules.ts`) needed no change.
- The extracted public-site components are pure presentation — no business rules inside. The
  layout still drives the shell through `content.getSettings()` and `content.getPublicNav()`.
- The page-hierarchy breadcrumb is enforced at the use case: a `Set` guards against cycles, and
  unpublished ancestors are filtered out before the chain is returned to the route.
- `src/app/(site)/layout.tsx` becomes `force-dynamic` to match the admin auth pages and
  `/sitemap.xml`, so `next build` does not need a running database or environment secrets.

## Known issues

None. The deferred public-site items (P3, P6, P9, P14) are all closed in this release. Markdown
rendering on the public site, block-based editor, public headless API, webhooks, comments,
301 redirects, revision history, automated backup/export scheduling, and multi-user roles remain
explicitly out of scope.
