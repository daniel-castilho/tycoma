# v0.3.1 — Lockfile refresh & doc-sync rule

Date: 2026-08-16

Patch release on top of `v0.3.0`. No runtime changes — only a clean `package-lock.json` so
`npm ci` resolves every transitive entry (including Prisma's `ContentType` / `ContentEntry`
optionals), plus the durable **lockfile rule** learned while recovering CI.

## Highlights

- **Lockfile refresh** (`07e8a41`) — `package-lock.json` was last committed before `v0.1.0`,
  while subsequent `npm install` runs on the dev box had grown the dep graph (the
  `ContentType` / `ContentEntry` models + Next.js wasm32 optionals). GitHub Actions' strict
  `npm ci` refused with `Missing: @emnapi/runtime@1.11.3 from lock file`. The lockfile is
  regenerated from a clean `node_modules` + `npm install` and re-validated with
  `rm -rf node_modules && npm ci --ignore-scripts`. CI run `31924663801` green in 2m20s.
- **Lockfile rule** (`e8177be`) — `AGENTS.md` § *Critical rules* (rule 10) and
  `docs/lessons.md` now require every `npm install` that mutates the lockfile to commit the
  updated `package-lock.json` in the same change set. Local sanity check:
  `rm -rf node_modules && npm ci`. Closes the failure mode documented under
  "npm ci is strict" in `docs/lessons.md`.

## Architecture notes

- No code changes in this release; no module, use case or wiring was touched.
- The fix is operational only. Future `prisma generate` pulls, dependency upgrades or
  platform switches must keep the lockfile in sync (see rule 10).
