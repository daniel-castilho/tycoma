# v0.5.0 — Security Hardening Phase A

Date: 2026-08-16

Fifth tagged release: **Security Hardening Phase A**. Closes the deferred security
follow-ups by raising the day-one resistance bar against stored XSS and trivial session
abuse — without 2FA, session redesign, or new npm dependencies. See
`tasks/tycoma-security-hardening-phase-a-{backlog,implementation-sequence,module-spec}.md`
for the full epic plan.

## Highlights

- **Security response headers on every response.** `next.config.ts` `headers()` ships:
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `X-Frame-Options: DENY`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - `Content-Security-Policy-Report-Only` baseline (`default-src 'self'`, `frame-ancestors
    'none'`, no `unsafe-eval`, S3 host allowed for images and `connect-src`). Phase A ships
    Report-Only because Next's admin still needs inline scripts for hydration; tightening
    to enforce is a follow-up.
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains` — **only** when
    `NODE_ENV === 'production'` AND `APP_URL` is `https://`, so local HTTP dev is not
    broken.
- **`AUTH_SECRET` production policy.** `parseEnv` in `src/shared/env.ts` now requires
  length ≥ 32 in production, rejects documented placeholders (`change-me-to-...`,
  `changeme`, `secret`, `dev-secret`), and rejects leading/trailing whitespace. Dev/test
  keep the 16-char minimum so local DX is unchanged. `next build` is detected via
  `NEXT_PHASE === "phase-production-build"` and treated as dev for the rule — the rule
  bites at runtime (`next start` and any real deployment). `src/shared/env-instance.ts`
  is the validated singleton; every adapter that previously did `import { env } from
  "@/shared/env"` was migrated there.
- **Session cookie attributes explicit and tested.** Single source of truth at
  `src/app/admin/_lib/session-cookie.ts` (`SESSION_COOKIE_OPTIONS`). Attributes: `httpOnly`,
  `secure` in production, `sameSite: 'lax'`, `path: '/'`, `maxAge` aligned with the JWT
  7-day expiry. Logout now writes an empty value with `maxAge: 0` using the same option
  object so the browser actually drops the cookie. `session-cookie.test.ts` asserts the
  shape so it cannot regress silently.
- **Media upload hardening.** `createUploadMedia` enforces:
  - `MAX_UPLOAD_BYTES = 10 MiB`
  - `ALLOWED_MIME_TYPES = ["image/jpeg", "image/png", "image/webp", "image/gif"]`
    (PDF/video/audio were in `v0.1.0`–`v0.4.0`; removed in Phase A — re-add only with
    explicit human approval).
  - `sniffMimeType` reads magic bytes (JPEG SOI, PNG signature, GIF87a/89a, RIFF/WEBP)
    and the declared MIME must match.
  - **SVG is blocked by both MIME (`image/svg+xml`) and extension (`.svg`)**.
  - Storage keys are server-generated (`media/${newObjectId()}.${ext}`) — no
    user-controlled path segments.
  - `next.config.ts` `images.dangerouslyAllowSVG` is now `false`.
- **Stored XSS defence.** The public site renders post/page bodies inside `<pre>` / `<p>`,
  so React auto-escapes any markup. No sanitizer library was added (Phase A rule). A new
  regression test (`src/app/(site)/_components/xss-regression.test.ts`) walks the entire
  `(site)/` subtree and fails if any file references `dangerouslySetInnerHTML`. If a future
  feature wants HTML, it must introduce a sanitizer library (a new npm dependency, which
  needs human approval per AGENTS.md rule 5) before removing the guard.

## Architecture notes

- No new module. No new public surface. All changes are inside existing hexagonal
  modules (`content`, `media`, `auth`, `shared`) or in the framework composition edge
  (`next.config.ts`, `src/app/admin/_lib/session-cookie.ts`).
- The rule-1 purity grep is still green — `domain/` and `application/` have zero
  framework/infrastructure imports.
- `src/shared/env.ts` no longer executes `parseEnv(process.env)` at the top level; the
  singleton lives in `src/shared/env-instance.ts`. Tests can import `parseEnv` directly
  and exercise dev/prod branches without touching `process.env`. `scripts/test-register.mjs`
  seeds `process.env` with safe defaults so tests that transitively load adapters don't
  crash on `process.env` reads.
- The `package.json` `test` script now wraps `src/**/*.test.ts` in single quotes so the
  shell doesn't pre-expand the glob (previously only `env.test.ts` was matched).

## Manual smoke checklist

- **Cookie flags (DevTools):** login → `tycoma_session` cookie has `HttpOnly`, `Secure` in
  production, `SameSite=Lax`, `Path=/`, `Max-Age=604800`. Logout → cookie value empty,
  `Max-Age=0`.
- **Response headers:** `curl -I http://localhost:3000/` shows `X-Content-Type-Options`,
  `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`, and
  `Content-Security-Policy-Report-Only`. `Strict-Transport-Security` is **absent** in
  dev.
- **Public XSS payload:** a post body of `<script>alert(1)</script>` renders as literal
  text inside the `<pre>` block; no script executes. The regression test enforces this.
- **Upload rejection:** upload `.html`, `.pdf`, `.svg`, or a PNG with a JPEG body → all
  rejected with a clear error. Upload a real PNG/JPEG/GIF/WEBP → accepted.

## Known issues / follow-ups (Phase B+)

- **JWT lifetime is still 7 days.** Tracked in `docs/lessons.md`. Phase B should redesign
  the session: short-lived access + refresh, server-side session store, optional
  re-binding on privilege escalation.
- **CSP ships as Report-Only.** Phase A does not enforce it. Phase B should map every
  Next inline script (`__NEXT_DATA__`, hydration helpers, etc.), generate nonces, and
  flip the header to `Content-Security-Policy`.
- **No 2FA / WebAuthn.** Single admin is the threat model; still fine for Phase A.
- **Media allowlist shrank.** PDF/video/audio were dropped in Phase A. If production
  needs them, they can be re-added with an explicit human-approved need and a per-type
  magic-byte sniffer.
- **No rate limit on `POST /api/media`.** Session is required, but a brute-force upload
  attempt is not yet bounded. The existing Redis limiter pattern is available for a
  follow-up.

## No new npm dependency

Confirmed: zero new packages were added in `v0.5.0`. The CSP, sanitizer guard, and
upload hardening all rely on platform features (`next.config.ts` `headers()`, React
auto-escaping) and pure TypeScript helpers in `src/shared/`.
