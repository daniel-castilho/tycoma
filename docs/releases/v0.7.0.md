# v0.7.0 — Security Hardening Phase C

**Date:** 2026-08-16
**Scope:** operational excellence (CI audit gate + Dependabot), residual
A/B debt (delete step-up, signed media URLs, security.txt), and runbook-grade
documentation for releases.

> Tag is not created by automation. The human runs `git tag -a v0.7.0 -m …`
> after the smoke from `docs/release-runbook.md` passes.

## Highlights

- **CI security gate.** `.github/workflows/ci.yml` now runs
  `npm audit --omit=dev --audit-level=high` right after `npm ci`. Critical
  and high vulnerabilities fail the build. The current tree reports
  *found 0 vulnerabilities*.
- **Dependabot weekly** for `npm` ecosystem (`.github/dependabot.yml`). Patch
  + minor updates batched; majors stay as individual PRs.
- **Step-up on destructive deletes.** Single delete (post / page / media)
  **and** the bulk posts delete all call `StepUpStore.has(actorId)` before
  touching the database. The 10-minute TTL Redis marker from Phase B is
  reused — no second step-up system. The admin UI now shows a
  `<StepUpHint />` block above each delete button on the affected pages.
- **SigV4 presigned media URLs.** Every read of a media asset URL goes
  through `media.getMediaWithUrl(id)` / `listMediaWithUrls()` so admin
  preview and the public site share one TTL constant
  (`SIGNED_URL_TTL_SECONDS = 30 min`). The presigning is implemented with
  `node:crypto` only — no `@aws-sdk/*` direct dep was added.
- **Backup manifest + checksum.** New `src/shared/backup/manifest.ts`
  defines the v1 schema (metadata + object keys only; binaries stay in the
  bucket) and a stable JSON canonicalisation. `scripts/backup-roundtrip.mjs`
  proves the export → SHA-256 → re-import loop without Docker.
- **RFC 9116 `/.well-known/security.txt`.** Rolling one-year `Expires`,
  driven by `SECURITY_CONTACT` (new env var, default
  `admin@example.test`). Operator must set the real address in production.
- **COOP on admin.** `Cross-Origin-Opener-Policy: same-origin` is added for
  `/admin/:path*` via `next.config.ts`. Public site is unchanged.
- **CSP stays Report-Only.** Documented as a Phase C residual in
  `docs/lessons.md`. Enforcing without a nonce pipeline was out of the
  "ops excellence" risk budget; the lesson entry explains why.
- **Playbook + runbook.** `docs/testing-playbook.md` gained a § Security
  regression block. `docs/release-runbook.md` is new and is the single
  procedure humans run before tagging.

## Lessons

`docs/lessons.md` gained two entries:

1. **CSP enforcement is a follow-up, not Phase C scope.** Enforcing without
   a nonce pipeline risked breaking the admin or public site. Phase C
   ships the Report-Only baseline + an explicit residual; enforcement is
   tracked in `tasks/` for the next milestone.
2. **SigV4 presigning without the SDK.** `node:crypto` (HMAC-SHA256) is
   enough for query-string presigning. The implementation matches
   https://docs.aws.amazon.com/AmazonS3/latest/API/sigv4-query-string-auth.html
   and validates against real S3 + LocalStack. Pulling `@aws-sdk/*` as a
   direct dep stays out of scope until a real need arises (lesson entry
   details).

## Migration notes

- Operators must set `SECURITY_CONTACT` to the real mailbox before
  pointing DNS at the production deployment. The default
  `admin@example.test` is invalid for RFC 9116 disclosure.
- Local dev / CI smoke must keep `npm audit --omit=dev` clean. If a
  transient dependency adds a high-severity advisory, follow the lessons
  entry: add the advisory id to `docs/lessons.md` with the removal date,
  not to the CI allowlist.
